## AI Agent (`src/app/admin/(app)/agent/`)

Natural language interface for managing students. The agent backend (tool implementations, system prompt, LangGraph graph) lives in `tuition-api/` — see `tuition-api/claude/agent.md` for full backend documentation. This section covers the frontend UI, SSE event contract, and the `[student_id:NAME:UUID]` token protocol.

**Frontend file:**
- **`features/agent/components/AgentChat.tsx`** — client component; the page at `agent/page.tsx` is a thin server component wrapper that just renders `<AgentChat />`

**`[student_id:NAME:UUID]` token protocol:**
- The agent backend appends one `[student_id:NAME:UUID]` token per affected student at the end of replies after create/update
- Tokens are extracted server-side before reaching the browser. The frontend receives clean text and a separate `ui_action` SSE event: `{ type: "ui_action", action: "student_links", payload: { studentLinks: [{ name, id }] } }`
- `AgentChat.tsx` handles `student_links` by setting `msg.students` on the pending message; one `"View NAME →"` `<Link>` is rendered per entry, displayed side-by-side bottom-right of the agent bubble

**AgentChat UI (`features/agent/components/AgentChat.tsx`):**
- `messages` state loaded on mount via `GET /api/agent/conversations/current` — returns `{ id, messages }` in one round trip. `conversationId` and `messages` are both set from this response. A `hydrated` flag (set `true` after the async init completes) gates the Send button.
- `messages` include `id` (DB UUID), `role` (`'user'` | `'agent'`), `content`, `isError?`, `steps[]`, and `timestamp` (ISO string from DB `created_at`).
- **Conversation persistence:** One permanent conversation row in Supabase. On mount, `GET /api/agent/conversations/current` returns (or creates) the latest conversation and its messages — no `localStorage` for conversation ID or mode. `clearChat()` calls `POST /api/agent/conversations/{id}/clear`, which wipes messages server-side; the same `conversationId` stays set in state.
- **History for retry/edit:** The backend uses `lg_contents` directly for retry (failed turns never update it) and `prev_lg_contents` for edit (state before the latest completed turn, stored on the conversation row). The frontend does no history slicing.
- **Typewriter effect:** `chunk` SSE events push text into `typewriterQueueRef` (a string buffer) and call `startTypewriter(pid)`, which drips `TYPEWRITER_CHARS = 3` characters every `TYPEWRITER_MS = 30ms` (~100 chars/sec) into `msg.content` via `setMessages`. The interval never stops itself mid-stream — it keeps dripping until the queue is empty. Two supporting refs: `streamDoneRef` (set `true` when `done` SSE fires) and `onDrainRef` (callback assigned on the `done` path). When the interval finds an empty queue **and** `streamDoneRef` is true, it calls `onDrainRef()` (which does `setLoading(false)` + clears `abortControllerRef`) then resets both refs. This separates "stream done" from "display done" — `loading` stays true while text is still dripping, so the input stays disabled and the Stop button stays visible until the last character is shown. A `loadingDeferredToTypewriter` flag in `send()` gates the `finally` block: when the typewriter takes ownership of cleanup, `finally` skips `stopTypewriter`, queue clear, `setLoading(false)`, and `abortControllerRef = null`. On error/abort paths, `loadingDeferredToTypewriter` stays `false` so `finally` handles everything immediately. Three helpers: `startTypewriter(pid)` (idempotent — no-op if interval already running), `stopTypewriter()` (clears interval), `flushTypewriter(pid)` (stops interval, dumps remaining queue into `msg.content` in one `setMessages` call — used by stopped/abort paths so the user sees all text received up to cancellation).
- **SSE streaming:** `send(retryMsgId?: string, editPayload?: { userMsgId: string; newContent: string })` — three branches, all sending to the backend with `conversation_id`:
  - **Normal send** (no args): creates a new user message + blank pending agent message, sends `{ conversation_id, message, request_id }`.
  - **Retry** (`retryMsgId`): resets the existing error bubble in-place, sends `{ conversation_id, retry_message_id }`.
  - **Edit** (`editPayload`): truncates `messages` display array to before the edited message, creates a fresh user message and pending bubble, sends `{ conversation_id, edit_user_message_id, new_content }`. No frontend history slicing needed.
  - `step` events append to the pending message's `steps[]`; `chunk` events push to `typewriterQueueRef` (not directly to `msg.content`); `done` defers loading cleanup to the typewriter; `stopped` and `AbortError` both flush the typewriter queue then call `markError()`; all error paths stop+discard the queue and set `isError: true`. `pendingIdRef` tracks the pending message ID; `receivedChunkRef` is set `true` on the first `chunk` event.
- The placeholder bubble shows three animated bouncing dots (custom `dot-jump` keyframe in `globals.css`, staggered 0/200/400 ms via inline `animationDelay`) while `content === ''` and `!msg.isError`; error/stopped bubbles show a static `⋯` instead. Transitions directly to steps + streaming text as events arrive. There is no separate loading bubble.
- Reply rendered via `<ReactMarkdown remarkPlugins={[remarkGfm]}>` — supports GFM tables, bold, blockquotes, links
- Custom `a` renderer: `mailto:` links render as `<span>` (prevents remark-gfm from auto-linking email addresses as clickable mailto links)
- Tool steps rendered above reply in a smaller muted section; UUID regex applied at render time (client-side cosmetic concern, not server-side)
- Input auto-focuses on mount and after each agent response via `useEffect([loading])`; disabled (and not focused) while the agent is executing
- **Inline download buttons:** `ChatMessage` carries optional `scheduleStudents` and `slotData` fields populated by `ui_action` SSE events (`action: 'download_schedule'` and `action: 'slots_ready'` respectively). When present, one or both download buttons render below the reply text. `downloadSchedulePng` and `downloadSlotsPng` use `drawScheduleToCtx` / `drawSlotsToCtx` from `src/shared/lib/timetable-canvas.ts` for pixel-identical output to the timetable tab PNG exports. `downloadCanvas` (also from the shared lib) handles the `<a>` click trigger.
- **Timestamps + retry row:** timestamp and retry button share one row below each bubble. User message timestamps are right-aligned (`justify-end`); agent message timestamps use `justify-between` (timestamp left, retry button right). `formatMessageTime(iso, now)` formats in MYT: time only (`"2:34 PM"`) if today, `"May 20, 2:34 PM"` if earlier this year, `"May 20 2025, 2:34 PM"` if a different year. Options objects (`MYT_DATE_KEY_OPTS`, `MYT_TIME_OPTS`, `MYT_DAY_MONTH_OPTS`) are module-level constants; `renderNow = new Date()` is computed once per render and passed in to avoid N allocations during SSE chunk re-renders.
- **Stop button:** the send button transforms into a ■ Stop button while `loading` is true. `stop()` is split on `receivedChunkRef`: if chunks have already arrived (text round) → `abortControllerRef.current?.abort()` (close the SSE connection immediately); if no chunks yet (tool round) → POST to `/api/agent/stop` with `{ requestId }` (soft stop: server finishes the current tool round, then emits `{ type: 'stopped' }`). In both paths, `stop()` immediately sets `isError: true` on the pending message via `pendingIdRef` (optimistic update — instant visual feedback regardless of server timing).
- **Retry button:** shown only on the **latest** agent message when `isError: true` — gated by `msg.id === latestAgentMsgId` (a `useMemo` mirroring `latestUserMsgId`). Covers both errors and user-stopped messages. `retry(msgId)` walks backwards through `messages` to find the preceding user message, then calls `send(msgId)` to replay in-place. Button is disabled while `loading` is true or while `editingMsgId !== null`. `isError` is loaded from the DB on mount.
- **Edit message:** `editingMsgId: string | null` and `editDraft: string` track the in-progress edit. `latestUserMsgId` is a `useMemo` that returns the `id` of the most recent user message. A `PencilSquareIcon` button appears to the right of the timestamp on the latest user bubble when `!loading && editingMsgId === null`; clicking it sets `editingMsgId` and pre-fills `editDraft` with the bubble's content. While `editingMsgId === msg.id`, the user bubble swaps its navy content div for a textarea styled to match the bubble shape (`rounded-2xl rounded-tr-sm border border-navy`); Send/Cancel buttons appear below. `confirmEdit()` clears `editingMsgId`/`editDraft` then calls `send(undefined, { userMsgId, newContent })`. Enter (without Shift) confirms, Escape cancels. Sending via the main input while an edit textarea is open closes the edit without sending the draft (normal send path calls `setEditingMsgId(null)`). `clearChat()` also resets both edit state values.
- **Voice input:** `speechSupported` is a `useState(false)` set to `true` in a `useEffect` after mount (checks `SpeechRecognition` / `webkitSpeechRecognition` on `window`; works in Chrome, Edge, Safari — not Firefox). Using `useEffect` rather than `useMemo` is required to avoid SSR/client hydration mismatch — the server renders `false` and the client corrects it after hydration. Mic button is hidden when unsupported. `toggleVoice()` starts/stops a `SpeechRecognition` instance stored in `recognitionRef`. `cleanupRecognition(focus?)` is a shared helper called by both `onend` and `onerror` to deduplicate state reset. An unmount-cleanup `useEffect` calls `recognitionRef.current?.stop()` to release the mic if the component unmounts while listening.
- **Agent endpoint:** all chat requests route to `/api/agent/chat`.

**SSE events consumed by the frontend:**

| Event type | Frontend action |
|---|---|
| `step` | Append `content` to `msg.steps[]` |
| `chunk` | Push `content` to `typewriterQueueRef`, start typewriter |
| `ui_action` | Handle `student_links` / `download_schedule` / `slots_ready` actions |
| `done` | Assign `onDrainRef` so typewriter cleans up loading state when queue drains |
| `stopped` | Flush typewriter queue, call `markError()` |
| `error` | Stop typewriter, discard queue, set `isError: true` |
