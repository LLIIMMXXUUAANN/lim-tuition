## Google Drive + Calendar integration (`src/services/google/`, `src/app/api/google/`)

Admin-only features for creating a student's Google Drive folder and weekly recurring Google Calendar event.

- **`src/services/google/auth.ts`** — `getOAuth2Client()`: reads refresh token from `settings` table, returns configured OAuth2 client. `newOAuth2Client()`: constructs a bare OAuth2 client from env vars (no DB read) — used by the one-time OAuth setup routes.
- **`src/services/google/drive.ts`** — `parseDriveFolderId(url)`: extracts and validates the folder ID from a Drive URL (shared by `updateStudentMeetDoc` and the delete route). `createStudentDriveFolder(auth, studentName, meetLink, classSchedule, mode)`: creates root folder in `GOOGLE_STUDENTS_FOLDER_ID`, sets anyone-with-link reader access, then branches on `mode` — `'My Python Syllabus'` creates 4 subfolders + Meet doc in parallel (`Promise.all`); `'Other Syllabus'` creates only the Meet doc. Atomic: deletes root folder on any failure so retries don't create duplicates. `updateStudentMeetDoc(auth, driveFolderUrl, studentName, schedule, meetLink)`: finds the "Google Meet Link" doc by name and rewrites its HTML content via `drive.files.update` — called automatically on reschedule.
- **`src/services/google/calendar.ts`** — `createWeeklyClassEvents(auth, studentName, schedule)`: creates a weekly recurring event for each class slot in `GOOGLE_CALENDAR_ID`; returns `{ meetLink, eventCount, eventIds }`. First slot gets a Google Meet conference (one Meet link per student); subsequent slots are created in parallel (`Promise.all`) and reference the same link in their description. Datetime strings are formatted as naive `YYYY-MM-DDTHH:MM:SS` (no Z) with `timeZone: Asia/Kuala_Lumpur` so Google Calendar interprets them as MYT regardless of server timezone. `slotDateTimes(slot)`: internal helper — anchors to the next occurrence of `slot.day` strictly after today (starting from tomorrow avoids "has today already passed?" logic), computes end from start + duration via `timeToMins` so end > start is always guaranteed. `updateWeeklyClassEvents(auth, studentName, schedule, existingEventIds, meetLink)`: **nuke-and-repave strategy** — (1) fetches all `existingEventIds` via `events.get` in parallel; (2) finds the **primary** event (the one with `hangoutLink` = owns the Meet conference); (3) if found, patches primary for `schedule[0]`; if not found (primary was deleted), creates a fresh event with `conferenceData` and a new Meet link; (4) deletes all other known events in parallel with creating fresh events for `schedule[1]+`; returns `{ eventIds, meetLink? }` where `meetLink` is only set when a new conference was generated. 410 Gone errors on delete are silently swallowed (already deleted = desired outcome). `findRecurringEventIds(auth, studentName)`: searches Calendar with `singleEvents: true` over a 90-day window (`maxResults: 200`), collects unique `recurringEventId` values from matching instances via a `Set<string>`, returns series master IDs — used by `sync-all`, `update-class-event`, and agent `update_student`.
- **`src/app/api/google/auth/route.ts`** — One-time OAuth setup: redirects admin to Google consent screen with Drive + Calendar scopes (tutor-only)
- **`src/app/api/google/callback/route.ts`** — OAuth callback: exchanges code for tokens, saves refresh token to `settings` table (tutor-only)
- **`src/app/api/google/create-student-folder/route.ts`** — POST `{ name, meet_link, class_schedule, mode? }`: creates the Drive folder structure (full with 4 subfolders for `'My Python Syllabus'`, Meet doc only for `'Other Syllabus'`), returns `{ url }` (tutor-only). `mode` defaults to `'My Python Syllabus'` if omitted or unrecognised. Requires `meet_link` to be set so the "Google Meet Link" doc is fully populated.
- **`src/app/api/google/create-class-event/route.ts`** — POST `{ name, class_schedule }`: creates weekly recurring Calendar events, returns `{ meetLink, eventCount, eventIds }` (tutor-only)
- **`src/app/api/google/update-class-event/route.ts`** — POST `{ name, class_schedule, event_ids, meet_link, drive_folder_url? }`: Phase 1 runs `findRecurringEventIds` and `updateStudentMeetDoc` in parallel (Drive uses the current Meet link); merges found IDs with `event_ids` from the request; Phase 2 calls `updateWeeklyClassEvents` with the merged set. If Calendar returns a new `meetLink` (primary was deleted and regenerated), re-runs `updateStudentMeetDoc` with the new link and clears `driveDocError`. Returns `{ eventIds, meetLink?, driveDocError }` — `meetLink` present only when a new Meet link was generated. `StudentForm` picks up `meetLink` from the response and updates both the form state and the DB payload. `invalid_grant` errors surface a friendly "Google auth expired" message. Called automatically by `StudentForm` on Save when the schedule has changed.
- **`src/app/api/google/sync-all/route.ts`** — POST, tutor-only: syncs all active students' Google Calendar events and Drive Meet docs to match the DB schedule. **Always** calls `findRecurringEventIds` for every student and merges results with `calendar_event_ids` from DB (catches rogue events not tracked in the DB, e.g. from previous bad syncs). If Calendar returns a new `meetLink` (primary regenerated), also updates `google_meet_link` in DB and re-runs `updateStudentMeetDoc`; Drive re-update failure surfaces in the sync notes. All students processed in parallel via `Promise.all`. Returns per-student `{ name, status, reason }` results. Surfaces `invalid_grant` errors with a reconnect message. Surfaced via `SyncAllButton` at the bottom of the students list.
- **`src/app/api/google/delete-student/route.ts`** — POST `{ drive_folder_url?, calendar_event_ids? }`: moves the Drive folder to Trash (`files.update({ trashed: true })`) and deletes all Calendar events; both ops run in parallel via `Promise.allSettled`. Both are non-fatal — returns `{ driveError, calendarError }` rather than throwing. Early-returns if both inputs are absent to skip the OAuth DB query. Called by `StudentForm` before hard-deleting the Supabase row.
- **`src/features/students/components/CreateDriveFolderButton.tsx`** — client button in `StudentForm`; accepts `mode: StudentMode` prop; label reads "Create Google Drive Folder (My Python Syllabus)" or "Create Google Drive Folder (Other Syllabus)" accordingly; disabled until both student name and Google Meet link are filled; on success auto-fills `google_drive_link`
- **`src/features/students/components/CreateCalendarEventButton.tsx`** — client button in `StudentForm`; disabled until student name and class schedule are filled; on success auto-fills both `google_meet_link` and `calendar_event_ids`
- **`src/features/students/components/SyncAllButton.tsx`** — always shown at the bottom of the students list; see Key components in CLAUDE-components.md

**Intended flow in student form:** fill name + schedule → click **Create Calendar Event** (Meet link + event IDs auto-fill) → click **Create Drive Folder** (doc written with actual Meet link). On subsequent edits, changing the schedule and clicking **Save Changes** automatically patches the Calendar events and rewrites the Drive doc (amber warning shown if Drive update fails, but save still proceeds).

**Required env vars:** `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `GOOGLE_STUDENTS_FOLDER_ID`, `GOOGLE_CALENDAR_ID`. `GOOGLE_LEC_TOPIC1_FILE_ID` is only required for `'My Python Syllabus'` students (validated before any Drive API calls; not needed for `'Other Syllabus'`).

**One-time setup:** visit `/api/google/auth` as admin to store the refresh token with Drive + Calendar scopes. OAuth app must have Drive API + Calendar API enabled in Google Cloud, with the admin email added as a test user.
